# 金屬製造異常警示通報系統

本專案為 Python／PySide6 Windows 桌面應用程式，透過 NI-DAQmx 讀取 USB-6211 的 `Dev1/ai0` 電壓，並按相同時間座標產生模擬電流。**每 1024 筆進行一次隨機模擬判定；AI 模型留待後續版本接入。** 右側顯示電壓、模擬電流及 Matplotlib 判定圖，OK 為綠色垂直線，NG 為紅色垂直線。

目前版本依 2026-10-14 簡報及使用者確認實作。第 1～8 節為現行操作，第 9 節保留 Email 設定教學；後方開發紀錄描述各次修改當時的版本，不能當作現行行為。

## 1. 功能現況

| 功能 | 行為 |
| --- | --- |
| 內部按鈕 | 預設硬體 FINITE 擷取 1024 筆，完成後可按「儲存」輸出 Excel＋PNG |
| 外部輸入1 | 按一下開始 CONTINUOUS 擷取，再按一下停止並自動儲存 Excel＋PNG |
| 外部輸入2 | 按住持續擷取，放開停止並自動儲存 Excel＋PNG |
| 按鈕接線邏輯 | `Dev1/port0/line0:3`，任一線高電位為按下，全部低電位為放開 |
| 1024 筆門檻 | 設定小於 1024 時不啟動 DAQ；停止後總數小於 1024 時捨棄本次、顯示提示，不判定、不儲存、不寄信 |
| 分段判定 | 每完整 1024 筆一段，分數 >= 0.5 為 OK；尾段不足 1024 筆保留原值但不判定 |
| 整次結果 | 任一段 NG 即為 NG；主畫面／Email 的分數採本次最低段分數；OK 比例為 OK 段數／已判定段數 |
| Email | 完整擷取成功後，包含 NG 且通知啟用時寄一封；不逐段寄信，儲存不寄新信 |
| 數位輸出 | 可設定 `Dev1/port1/line0～3` 的單一線；NG 段使輸出 ON，下一次有效按下事件 OFF；未指定通道時停用 |
| 模型及第二類比通道 | 模型僅保存路徑，不載入；第二通道欄位顯示預留，電流持續為程式模擬，不讀 ai1 |
| 外部檔案 | 依簡報「這項可以先不用」，本版未提供外部檔案輸入 |

**模擬 NG 仍會依設定寄信及輸出燈號，不能視為真實焊接異常。** 新建設定預設停用 Email、停用數位輸出並使用內部按鈕。既有帳號、SMTP、通道、取樣率及未知欄位保留。

## 3. 安裝、啟動與設備確認

1. 安裝 NI-DAQmx 驅動，接上 USB-6211，先在 NI MAX 確認裝置名稱及 Self-Test。
2. 關閉會占用設備的 NI MAX Test Panels。類比輸入預設 DIFF、±10 V，接線需符合設備規格。
3. 使用既有虛擬環境啟動：

```powershell
.\.venv\Scripts\python.exe main.py
```

新環境先建立虛擬環境並依 `requirements.txt` 安裝。現有環境已包含 PySide6、nidaqmx、openpyxl、matplotlib，本次未新增依賴。

USB-6211 提供 4 路靜態數位輸入 `PFI0～3 / port0/line0～3` 及 4 路數位輸出 `PFI4～7 / port1/line0～3`；簡報的 `port0/line0:7` 不適用於本機型。依使用者確認監看 `port0/line0:3`，任一線高電位觸發。參考 [NI USB-6211 規格](https://www.ni.com/docs/en-US/bundle/usb-6211-specs/page/specs.html)（2026-10-15 查核）。照片無法驗證實際電氣接線；本次未操作實體 I/O。

## 4. 工程設定與操作

按「工程設定」可設定 DAQ 裝置、第一路類比輸入、數位輸入範圍、觸發線、有效電位、數位輸出、內部模式取樣點數、取樣率、觸發模式、模型路徑、儲存路徑、收件帳號及通知裝置編號。DAQ 名稱與通知裝置編號分開，保留原 Email 的業務識別。

- 預設為 1024 筆、1000 samples/s，第一張圖為 ai0 實測電壓，第二張圖為模擬電流。工程設定的「取樣點數」只控制內部有限擷取的總量，辨識窗長固定 1024。
- **如果既有 config.json 仍設定 1000 筆，程式會保留該值並提示不足，請在工程設定改為 1024 後儲存。** 本次開發不直接改寫本機設定。
- 內部模式：按「擷取」收齊設定筆數，預覽每完整 1024 筆更新判定圖；完成後按「儲存」輸出 Excel＋PNG。
- 外部輸入1：按一下開始；放開不停止；下一次按下停止、自動儲存。再下一次按下可開始新的一次。
- 外部輸入2：按下開始；只要四條輸入中仍有一條高電位就繼續；全部回到低電位後停止、自動儲存。沒有額外長按等待秒數。
- 啟用監看時若按鈕已按住，必須先放開再按下。輸入穩定至少 50 ms 才產生事件；這是軟體輪詢及去彈跳，不是硬體精準觸發。
- 外部模式最多取得 60 秒或 100000 筆（先到者）後自動結束並儲存，避免無限累積記憶體。達上限後須重新操作按鈕，不自動重啟。
- 停止時不等待補足 1024 筆，總數不足就提示並捨棄。例如 300 筆不採用；2150 筆則判定 2 段，保留最後 102 筆但不判定。
- 數位輸出通道空白即停用。啟用後任一 NG 段設 ON，下一個有效按下事件設 OFF；模式1的停止按下也會清除燈號。設定重載、關閉及 I/O 失敗清理時嘗試 OFF 並釋放 Task。實際設備拔除時軟體不能保證硬體腳位狀態。
- 內部模式若啟用數位輸出，仍監看 DI 作為燈號復歸，DI 不啟動擷取。
- 工程設定開啟時暫停數位監看；離開後重建監看並要求先放開按鈕。儲存 Excel／PNG 期間不接受新擷取，期間的按鍵事件不排隊成下一次擷取。

工程設定按「儲存」先驗證全部參數，成功寫入 JSON 後才更新使用中設定；按「離開」不保存。保存使用暫存檔替換，避免寫到一半破壞原設定。模型路徑目前不會被載入或執行。

## 5. 設定檔

設定檔、UI 路徑以 `main.py` 所在目錄為基準，`save_path` 的相對路徑也相對於專案。首次啟動缺設定檔時建立預設值；已有檔案時只在記憶體補入缺少欄位，使用者按儲存才寫回。

```json
"daq": {
    "channel": "Dev1/ai0",
    "terminal_config": "DIFF",
    "min_voltage": -10.0,
    "max_voltage": 10.0,
    "sample_rate": 1000.0,
    "samples_per_channel": 1024
},
"engineering": {
    "trigger_mode": 0,
    "di_channel": "Dev1/port0/line0:3",
    "trigger_line": "any",
    "active_high": true,
    "do_channel": "",
    "model_path": ""
}
```

`trigger_mode`：0＝內部、1＝外部按一下、2＝外部按住。`trigger_line` 可為 `any` 或輸入範圍內的整數線號；預設 `any` 為使用者確認的任一線。數位輸入只接受同一 DAQ 裝置的 port0/line0～3 或連續範圍，輸出接受同裝置 port1 的單一線。

類比 `sample_rate` 須大於 0 且不超過 250000，`samples_per_channel` 須為 1024～100000 整數且請求時長不超過 60 秒，實際可用速率由設備決定。`terminal_config` 支援 DIFF、RSE、NRSE。舊 `gateway1`／`gateway2`、`channel2` 及未知欄位保留，主畫面的通道標籤現在顯示實際 ai0 及模擬來源，不再以舊 IP 當作 DAQ 來源。

## 6. 擷取、停止與關閉

類比及數位 I/O 各由背景執行緒持有 Task，UI 用 QTimer 接收預覽、按鈕事件及完成結果。內部有限讀取約 0.1 秒一段；外部持續讀取當時可用樣本，停止時只讀取收到停止要求時已在緩衝區的樣本，不等待湊數。樣本索引／DAQ 實際取樣率決定時間軸及模擬電流相位。

`stop` 代表停止並保留足量資料；關窗或數位 I/O 故障使用 `cancel` 捨棄本次。失敗時保留上一批成功資料與判定圖，不自動把上一批當成本次儲存。關閉期間忽略晚到結果及預覽，取消待寄通知、等待正在寄送的通知與 DAQ／數位工作釋放資源。驅動初始化等仍可能受驅動影響，讀取 timeout 不代表關閉總時間上限。

圖上分段結果為模擬預覽，只有整次擷取成功才新增一筆歷史、產生一次 Email 通知。歷史目前只保留本次執行期間摘要。

## 7. Excel 與 PNG 輸出

輸出至 `save_path/YYYY/MM/DD/YYYYMMDD_HHMMSS_001.xlsx` 與相同名稱 `.png`；任何一個檔名已存在就遞增編號，不覆蓋。正常寫入例外會清除這次新建的半成品，保留記憶體資料供重試。作業系統／程序強制終止不在成對寫入完成保證範圍內。

| 工作表 | 內容 |
| --- | --- |
| 擷取資料 | 原六欄 Timestamp、Voltage、Current、Score、Prediction、CurrentSource；原值全數保留，分數／判定改為所屬1024筆段落的結果，尾段分數空白且標示未判定 |
| 擷取設定 | 本次來源、通道、實際取樣率、數量、電流模擬參數、時間；另含1024窗長、尾段數量、整次結果、最低分數及OK比例 |
| 分段判定 | 每段起始／結束樣本索引（從0起）、分數、OK／NG與模擬來源 |

Timestamp 沿用儲存時間，非逐筆取樣時間。PNG 採簡報三圖格式：電壓藍線、模擬電流橘線、判定綠／紅垂直線與 OK 比例；圖中明確註明模擬電流與尚無 AI。前兩圖橫軸為樣本索引，結果圖為判定段號。舊檔案不改寫、不轉換。

## 9. NG Email 通知與設定教學

### 觸發與畫面狀態

`complete_capture()` 取得分數及結果後，沿用擷取工作者記錄的完成時間，先保留擷取結果與歷史，再呼叫 `notify_capture_completed()`。只有 NG 且啟用通知才排入背景工作；每次 NG 各一封，不比較前一次結果。儲存 Excel、更新歷史與帳號設定都不寄信。

- 收件人、裝置號碼、完成時間、分數、結果及寄件設定都是當次不可變快照；工作者不讀取 `current_score` 或 `current_prediction`。密碼只在執行時從快照所指定的環境變數取得，不放進快照或設定檔。
- 繁體中文主旨與內文使用 UTF-8；分數兩位小數、擷取時間 `YYYY-MM-DD HH:MM`；沒有附件。
- 在既有底部 `QStatusBar` 加入獨立 Email 文字，不修改 `.ui` 配置，也不覆蓋 `lblStatus` 的擷取／儲存狀態。
- 顯示未啟用、等待寄送、寄送中、已交給郵件伺服器、設定錯誤或寄送失敗。最新擷取以編號與完成時間標記；較舊通知的結果只更新對應歷史列「預測結果」儲存格的滑鼠提示，不冒充最新結果。
- 「已交給郵件伺服器」僅代表 SMTP 接受，不能保證進入收件匣。關窗後歷史及通知狀態不持久化。

### 寄件設定

保留 `config.json` 原有頂層欄位，新增下列區塊（專案已加入，交付值如下）：

```json
"email": {
    "enabled": false,
    "smtp_host": "smtp.gmail.com",
    "smtp_port": 465,
    "security": "ssl",
    "username": "",
    "sender": "",
    "password_env": "METAL_SMTP_PASSWORD",
    "timeout_seconds": 20
}
```

| 欄位 | 要填寫的內容 |
| --- | --- |
| 頂層 `account` | 單一收件 Email；也可從「帳號設定 → 帳號」修改並儲存，下一次 NG 即使用新地址 |
| `email.enabled` | 全部設定完成後將 `false` 改成 `true`（JSON 布林值，不加引號） |
| `email.smtp_host` | 郵件服務商提供的 SMTP 主機；Gmail 範例為 `smtp.gmail.com` |
| `email.smtp_port` | Gmail SSL 使用整數 `465`；STARTTLS 使用 `587` |
| `email.security` | `ssl` 或 `starttls`；TLS 失敗不會改用明文 |
| `email.username` | SMTP 登入帳號；Gmail 為完整寄件信箱地址 |
| `email.sender` | 寄件 Email；Gmail 通常填與 username 相同的地址，其他地址須先獲服務商授權 |
| `email.password_env` | 保留 `METAL_SMTP_PASSWORD`，或填另一個環境變數名稱；此欄不是密碼 |
| `email.timeout_seconds` | 大於 0 的網路操作逾時秒數，預設 `20` |

地址驗證支援單一一般 ASCII 信箱，不接受多位收件人清單、顯示名稱或國際化信箱。舊設定沒有 email 區塊時仍可啟動；部分欄位缺少時逐一補值。啟用後設定不足會顯示原因，不影響擷取及儲存。

### Gmail 兩步驟驗證與應用程式密碼

以下官方頁面已於 **2026-09-17** 查核：

1. 開啟 [Google 帳戶](https://myaccount.google.com/)，進入「安全性與登入」，在「登入 Google 的方式」啟用兩步驟驗證，依畫面完成。見 [Google 官方：開啟兩步驟驗證](https://support.google.com/accounts/answer/185839?hl=zh-Hant)。
2. 前往 [應用程式密碼管理](https://myaccount.google.com/apppasswords)，為本系統建立應用程式密碼，將產生的密碼放入下一節的 Windows 環境變數。不要填一般 Google 登入密碼，也不要貼到對話、程式碼或 JSON。應用程式密碼需要先啟用兩步驟驗證；公司／學校帳戶、只使用安全金鑰或開啟進階保護的帳戶可能不提供此選項。變更 Google 帳戶密碼後，需要重新建立應用程式密碼。見 [Google 官方：使用應用程式密碼](https://support.google.com/accounts/answer/185833?hl=zh-Hant)。
3. 使用 `smtp.gmail.com`、SSL 465，或 STARTTLS 587；以完整寄件地址及應用程式密碼驗證。見 [Google Workspace 官方 SMTP 設定](https://knowledge.workspace.google.com/admin/gmail/send-email-from-a-printer-scanner-or-app?hl=en)。

Gmail 僅是設定範例。本版採 SMTP 帳號／密碼驗證，**不直接支援 OAuth**；若服務商或機構政策要求 OAuth，需另行整合，不能以此實作繞過要求。

### Windows 設定密碼環境變數

持久設定方式：Windows 搜尋「編輯帳戶的環境變數」→「使用者變數」→「新增」，名稱填 `METAL_SMTP_PASSWORD`，值填剛產生的應用程式密碼並儲存。密碼不要存進專案檔案。環境變數並不是加密的憑證保管庫，同一帳戶下的程式可能讀取。

若只要在目前 PowerShell 暫時使用，可執行以下互動輸入；密碼不會出現在輸入畫面或命令歷史中的文字常值：

```powershell
$smtpSecret = Read-Host '請輸入 SMTP 應用程式密碼' -AsSecureString
$smtpCredential = New-Object System.Net.NetworkCredential('', $smtpSecret)
$env:METAL_SMTP_PASSWORD = $smtpCredential.Password
Remove-Variable smtpSecret, smtpCredential
.\.venv\Scripts\python.exe main.py
```

持久環境變數儲存後，**關閉並重新開啟本系統，以及用來啟動它的 PowerShell／Windows Terminal、IDE 或其他啟動器**，再啟動本系統；既有 Python 程序不會自動取得新值。如果啟動器仍繼承舊環境，可登出 Windows 後重新登入。上方暫時設定只影響該 PowerShell 與從它新啟動的子程序，不會更新已開啟的系統視窗。

直接編輯 JSON 的 Email 設定後也請重啟本系統。「帳號設定」儲存收件地址則會即時重載，無須重啟；已排入的通知保留舊快照。

### 手動驗證一封 NG 通知

1. 先設定自己可查看的收件地址 `account`，填好寄件 `username`、`sender`、SMTP 設定及密碼環境變數。
2. 將 `email.enabled` 改為 `true`，儲存 JSON，從已取得環境變數的終端機啟動本系統。
3. 按一次「擷取」。若為 OK 就不寄信，可再按一次；**首次出現 NG 後停止繼續擷取**，等待底部 Email 狀態變為「已交給郵件伺服器」或可理解的錯誤原因。
4. 到收件匣及垃圾郵件匣確認主旨、裝置號碼、該次擷取時間、兩位小數分數及 NG；郵件不含附件。可按「儲存」確認不會再次寄送。
5. 測試後若尚不準備持續寄信，將 enabled 改回 false 並重啟系統。不要在狀態尚不明時反覆觸發 NG，因為每次新擷取都是獨立通知。

**`predict()` 目前仍產生隨機分數與判定，通知啟用後所有模擬 NG 都會寄信，不代表真實設備異常。**

### 背景工作、錯誤與關閉策略

- 一條非 daemon Python 背景執行緒依序寄送；最多 100 筆等待通知，超過時該次顯示「佇列已滿、本筆未排入」，仍保留擷取結果。不會隨擷取次數增加執行緒。
- 工作者只寫入 thread-safe 結果佇列；主執行緒每 100 ms 由 QTimer 取得結果並更新 Qt 控制項。
- SMTP 使用系統信任憑證與主機名稱驗證。SSL 直接加密；STARTTLS 成功後才登入。無明文降級、無自動重試。
- 登入失敗、收件人被拒、網路逾時、TLS 或其他錯誤都會顯示分類原因；終端機只記錄擷取編號及錯誤類型，不輸出密碼、SMTP 完整回應、認證資料或 traceback。逾時／斷線有可能發生在伺服器已接受後，寄送結果可能不明。
- 按離開或標題列關閉時，取消尚未完成的 NI 擷取、取消尚未開始的通知、停止接受新通知。如果仍有擷取工作或正在寄送的一封，視窗暫緩關閉，事件迴圈持續運作並顯示等待文字；擷取與寄信工作者均結束且 join 後才關閉。
- 不強制殺死執行緒。`timeout_seconds` 是每次 socket 操作的逾時，**不是整封信或關閉等待的總時間上限**；多次 SMTP 操作及作業系統 DNS 解析可能使等待較長。直接呼叫 `QApplication.quit()` 時，事件迴圈退出後仍會取消擷取、取消等待佇列並 join 兩種工作者；此替代路徑不再提供等待畫面。強制終止程序不在優雅關閉保證範圍內。
- 待寄通知只在記憶體，不持久化；關閉取消後不會在下次啟動補寄。
